# Канвас на React Flow

Редактор цепочки «текст → генератор → результат», сохранение графа через REST и тестовая генерация изображения. Бэкенд из задания не менялся.

Исходные условия: [задание](docs/ASSIGNMENT.md) · [API](docs/INTEGRATION.md) · [критерии](docs/EVALUATION.md). Для отклика нужен ещё [checkout](https://github.com/artemkilox/frontend-checkout-challenge).

## Запуск

Нужны Node.js 24.x и npm 11.x.

```sh
git clone https://github.com/artemkilox/frontend-canvas-challenge.git
cd frontend-canvas-challenge
npm ci
npm run dev
```

- API: http://127.0.0.1:4001 (Swagger: http://localhost:4001/docs/)
- Фронтенд: http://localhost:3000

По отдельности: `npm run dev:api` и `npm run dev:web`.

Сборка:

```sh
npm run build
npm start
npm run start:web
```

Адрес API для фронта по умолчанию `http://127.0.0.1:4001`. Другой — `apps/web/.env` из `apps/web/.env.example`.

Открыть `/` — создаётся пространство с готовой цепочкой и переход на `/spaces/{id}`. F5 на этом URL открывает то же пространство.

Сброс данных API: остановить сервер, `npm run data:reset`.

Корневой `npm run check` — формат, тесты бэкенда и OpenAPI. `npm run smoke` — при запущенном API.

## Как устроен фронтенд

Workspace `@canvas/web` (Next.js App Router). Подробнее: [apps/web/README.md](apps/web/README.md).

- Один HTTP-клиент (`apps/web/src/api/client.ts`): база URL, JSON, пустые `204`/`304` без `.json()`, разбор ошибки `{error}`. Ответ — сам ресурс, без обёртки `data`. `X-Request-Id` берётся из ответа. Компоненты не вызывают `fetch`.
- Ресурсы (`src/api/resources`) описывают путь и тело. ETag графа читается из заголовка и уходит в `If-Match` и в `graphETag`.
- Опрос генерации (`src/api/poll.ts`) общий: AbortSignal, стоп при финале или уходе со страницы.
- Канвас: `src/features/canvas`. Правила связей и проекция RF ↔ API — в `src/domain`.

Отказ генерации — `status === failed` при HTTP 200, не ошибка транспорта. Картинка показывается только при `succeeded` и только в ноде `resultNodeId` этой попытки.

## Debounce и очередь PUT

После правки UI обновляется сразу, PUT уходит через 500 мс после последней. Пока PUT в полёте, новые правки копятся; ответ не затирает более новый черновик — уходит следующий PUT с новым ETag. Параллельных PUT одного графа нет. Кнопка генерации сбрасывает таймер, дожидается очереди и только потом делает POST. При ошибке сохранения генерация не стартует.

Конфликт `412`: черновик остаётся, нужно явно перечитать серверный граф.

## Обработка данных

Проверка связи и удаление рёбер удалённой ноды — один проход по массиву edges, без `.map().filter()`. Типы нод собираются в `Map` за один проход (`typeById`). Список генераций приходит от новых к старым: первый раз увиденный `resultNodeId` остаётся в `Map`, повторный линейный поиск по id не делается. `simulateFailure` живёт только в UI и в PUT не попадает.

## Принятые решения

- Next.js App Router, канвас только на клиенте (`dynamic`, `ssr: false`).
- CSS Modules и имена БЭМ, без UI-kit.
- Пути API заданы в клиенте по контракту, не через `links`.

## Проверенные сценарии

- Создание space, три типа нод, текст и перемещение сразу видны.
- Связи только текст → генератор → результат; лишний вход/выход не создаётся.
- Удаление ноды снимает её связи; граф сохраняется.
- Генерация после ввода до сохранения; картинка в связанном результате.
- Имитация отказа, повтор с новым ключом.
- Перезагрузка восстанавливает граф и результат; незавершённая генерация продолжает опрос.

## Недоработки

- Нет деплоя, undo, совместного редактирования и мобильной вёрстки (по заданию не нужны).
- Слияние двух версий графа при конфликте не делается — только перечитать сервер.
- Список пространств не показывается: новое space создаётся с `/`.
